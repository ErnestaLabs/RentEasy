# RentEazy App UI Contract

This folder is the app UI lane.

## Ownership

- `src/app/screens/*`: presentational screen components. Claude can restyle these.
- `src/app/components/*`: presentational app chrome/components. Claude can restyle these.
- `src/App.jsx`: still the app container for now. Codex owns state, handlers, Clerk/auth, preview gating, and data contracts.
- `src/lib/feedEngine.js`: Codex-owned ranking and signal logic.
- `server/**`: Codex-owned backend/API/persistence.

## Stable Props

These are the UI-facing data/handler contracts currently passed from the container:

- `profile`: real local app profile state, synced with Clerk when configured.
- `posts`: local persisted feed posts seeded from demo data and user-created posts.
- `feedItems`: ranked feed items generated by `buildRentEazyFeed`.
- `visibleFeedItems`: preview-gated feed subset for anonymous visitors.
- `rankedSwipeCards`: locally ranked swipe cards using `scoreSwipeCard`.
- `likedIds`, `savedIds`, `followedIds`, `comments`: local persisted engagement state.
- `matches`, `matchMessages`: local persisted match/message state.
- `groups`, `groupMemberships`: local persisted groups state.
- `partnerOffers`: local persisted partner/perks state.
- `reports`, `shares`, `boosts`, `purchases`, `wallet`: local persisted commerce/safety state.
- `usageLimit`, `remainingSwipes`: local persisted daily swipe allowance state.

Handlers are stateful and Codex-owned:

## Wired vs Placeholder Notes

- Feed ranking: wired locally through `src/lib/feedEngine.js`; backend feed API exists separately but the app screen still uses local/demo-backed state.
- Preview gating: wired and active. Anonymous `/app` users get limited/blurred preview behavior.
- Swipe limits: wired locally through `usageLimit`; not yet server-enforced.
- Posts/comments/likes/saves/follows/reports/shares: wired locally with persistent browser storage; backend persistence is still in progress.
- Messenger: wired locally through `matches` and `matchMessages`; no paid third-party text messaging.
- Billing/micro-products: UI and local purchase records exist; Clerk Billing integration is scaffolded, not final production billing.
- Groups/perks/resident/professional panels: local/demo-backed scaffolds with stable shapes.

## Claude UI Rules

Restyle markup/classes/motion in `src/app/**` only.
Do not change handler names, prop meanings, state keys, preview gating, ranking, auth, or backend files.
